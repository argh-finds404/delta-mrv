# 08 — AI Contract

Authority over: how Gemini is used, and the limits it may never cross.

---

## 1. The one-line rule

> **AI produces one low-weight advisory finding. It can never change a status,
> approve anything, reject anything, or be presented as proof.**

If a proposed feature requires the AI to decide, the answer is no.

## 2. SDK

`@google/genai`. The older `@google/generative-ai` is the previous-generation
package and is on the forbidden list.

The model name comes from `GEMINI_MODEL`, never a string literal in code. The
free tier covers the Flash and Flash-Lite tiers; resolve the current model
name at setup time and record it in `docs/DEPENDENCY_LOG.md`.

## 3. Where it runs

`src/server/services/ai-audit.service.ts`, invoked as a **job**, never inline
in a request. A submission is complete and has all deterministic findings
before the AI job runs. The AI result arrives later and appends one more
finding.

This ordering matters: a submission must be fully reviewable with the AI
finding absent.

## 4. What it is asked

Qualitative observation only, on a before/after pair:

- Does the imagery appear consistent with the stated activity type?
- Are there visible differences between before and after?
- Are there obvious visual inconsistencies worth a human's attention?
- Does anything suggest the image is a photograph of a screen, a stock
  image, or synthetic?

### Never asked

- To count anything ("how many trees")
- To estimate a percentage of coverage, density or health
- To authenticate the photograph
- To determine where or when it was taken
- To produce a risk score, probability or confidence number that the system
  then acts on
- To decide anything

Quantities the AI invents read as data and are not data. Counting is on the
CUT list in `docs/01-FEATURE-LOCK.md`.

## 5. Output contract

The response is parsed and validated with Zod. Anything that fails validation
is discarded and recorded as `ai_unavailable` — never partially trusted,
never repaired by hand.

```ts
const AiObservation = z.object({
  consistentWithActivity: z.enum(["appears_consistent","unclear","appears_inconsistent"]),
  visibleChangeBetweenImages: z.enum(["clear","subtle","none","indeterminate"]),
  observations: z.array(z.string().max(300)).max(5),
  concerns: z.array(z.string().max(300)).max(5),
  recommendsHumanAttention: z.boolean(),
});
```

Enums, not free numbers. Short bounded strings, not essays. Five items
maximum — a reviewer will not read twenty.

## 6. Stored as a finding

```
kind:     AI_OBSERVATION
severity: INFO    (or LOW when recommendsHumanAttention is true)
reason:   a sentence composed from the validated fields
evidence: { model, promptVersion, raw: <validated object>, latencyMs }
```

`severity` never exceeds `LOW`. The derived score weights `AI_OBSERVATION`
at a fraction of any deterministic finding, and the weight is visible in the
score breakdown.

## 7. Untrusted input

The image is attacker-controlled. A photograph can contain text instructing
the model to say the evidence is authentic.

Mitigations:

- The system prompt states that any text inside the image is content to be
  described, never an instruction to follow.
- The schema has no field through which an instruction could take effect —
  there is no `approved` boolean and no free-form status.
- Output is validated structurally; prose fields are rendered as escaped
  text, never as markup.
- The model output never reaches a database write path other than the
  finding row.

Document this in `docs/THREAT_MODEL.md` as "prompt injection via evidence
imagery".

## 8. Failure behaviour

| Condition | Result |
|---|---|
| No `GEMINI_API_KEY` | `ai_unavailable`. No error surfaced to the user. |
| Quota exhausted (429) | `ai_unavailable`. Job retried on the next drain with backoff. |
| Timeout (15 s) | `ai_unavailable`. |
| Schema validation failure | `ai_unavailable`. Raw response logged for debugging, never shown to a user. |
| Model name 404 | `ai_unavailable`. Surfaced to admin as a configuration problem. |

`ai_unavailable` is a neutral grey state in the Lab, not a red error. The
reviewer sees "AI observation not available for this submission" and carries
on. Nothing about the review is blocked.

## 9. In the interface

The AI card is visually subordinate: below the deterministic findings, in
muted surface treatment, headed **Advisory observation — not evidence**.

It always carries the model name and a one-line statement that this output
is an opinion generated by a language model, is not verified, and was not
used to decide anything.

Never style it like a verdict. Never give it a confidence bar. Never let it
sit above the forensic findings in the reading order.

## 10. Cost discipline

- One AI call per submission, covering both images in a single request.
- Never re-run on page view. The finding is stored.
- Deterministic replay (`S6`) skips the AI call and reuses the stored finding —
  AI output is not reproducible and is excluded from the replay assertion.
- Images are downscaled before sending; the original is never transmitted at
  full resolution.
